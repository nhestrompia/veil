# Remaining agent-free gaps

Status after milestone 150: the combined minimal browser exists at dist/AgentFreeBrowserPreview.app. It supplies one page, an address field, navigation controls, and the measured built-in keyboard route. Its agent-free claim remains unproven. The previous physical session expires under its one-hour watchdog. No current physical session exists.

The two requirements remain separate. Disclosure prevention stops recovery of a fresh page-only secret. Action prevention stops an external agent from completing a website task, including blind operation. Both require usable human access on the same final build.

Loaded-page trials now cover Google, Wikipedia's search page, and GitHub's search page in the actual preview. The user confirms visible pages before the attempts and unchanged empty search fields afterward. A directed-window key-code route submits the fixed phrase in each readable reference and fails in the preview. The subagent independently repeats the Wikipedia attempt. Scoped window captures are black with readable references. External search and JavaScript URL entry receive explicit browser refusals on GitHub. Four other native routes remain uncalibrated. These bounded results do not establish a general guarantee. See [loaded-page findings](loaded-public-website-findings.md) and the [challenge commands](public-website-challenges.md).

## Protection work that remains

1. Close the capture gap on the actual preview. Window-scoped continuous capture returns 948 black complete frames with readable controls before and after. App-filtered display capture delivers no complete candidate frames and remains inconclusive. The new unfiltered recorder has effective Screen Recording access. The approved layout update passes one metadata-only fullscreen control. Later readable capture controls fail on focus or an overlapping system alert. Neither failure proves protection. First-display, resize, fullscreen, and other transitions remain open.
2. Complete semantic and script access tests. One bounded renderer token comparison recovers the readable control's marker and no preview marker. Other renderer reads fail their controls. Installed private-framework metadata identifies client channel interfaces. Three external discovery controls find no reference fixture. Later controls report a connected local target, but explicit identifier and listing requests still find no owned application. The later lifecycle trace records target disappearance and an own-client webinspectord validation failure. A signed app-bundle comparison also loses its target before discovery. Initial connection flags do not prove daemon admission. No calibrated external inspector attachment client tests the preview. A missing TCP listener does not establish protection against Cocoa's XPC transport. Keyboard observation also needs its separate preview result.
3. Close zero-input action routes on the final image. Five matched native-input routes produce 206 explicit refusals and no new action in one physically completed preview. Another route fails its control. Earlier shared-browser diagnostics complete website actions through focus and timing changes without admitted input. Their later mitigations and identity-isolated renderer are separate experiments. The current preview does not integrate those protections. Repeat the successful attack fixtures on the final architecture before an agent-free claim.

The evidence is in [stream results](preview-stream-live-findings.md), [compositor calibration](preview-compositor-layout-update-findings.md), [signed inspector comparison](inspector-bundle-findings.md), [renderer reads](preview-renderer-live-findings.md), [native input](preview-native-input-findings.md), [focus actions](page-feature-findings.md), and [clock actions](clock-channel-findings.md).

## Human use and release acceptance

The current candidate supports this Mac's measured built-in keyboard and US ASCII. Mouse input is disabled. Unicode, input methods, broad website compatibility, and the PRD's human-use targets remain unmet. These are explicit usability limits, not additional agent defenses. A physically black page cannot pass.

Final validation needs one report for the same final image and declared attack suite. It must cover browser transports, accessibility, synthetic and blind input, captures, lifecycle changes, and enabled exports or session residue. Each claimed block needs a working reference. Fresh secrets and task outcomes come from an independent oracle. Required inconclusive results prevent acceptance.

A finite attack suite supports a bounded result about the tested capabilities. It cannot prove protection against all websites and future agents. The project must not call an unfinished test, a permission failure, or a diagnostic-only defense an agent-free MVP.

## Scope that stays fixed

Root attacks, modified browser images, kernel exploits, malicious hardware, and external cameras remain outside the PoC threat model. An agent's separate browser and unrelated API credentials are also outside the browser claim. No new browser feature expansion is needed to finish the protection research.

The cross-user renderer work addresses a measured signal bypass, but it does not supply the preview's visible output and physical input. Do not treat that component's success as integrated protection. The remaining work concerns real enforcement and validation. It is not a missing tab bar or bookmark manager.
