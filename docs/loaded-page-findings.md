# External attacks after diagnostic page startup

All 33 reference attempts completed a disposable website action. Three candidate processes each completed one private startup action, then received eleven external attack attempts. Twenty-seven native attempts reached the input gate and were refused. No candidate recorded a new accepted action.

The native routes cover three CGEvent source states, curved movement, keycodes, two PID-directed keyboard variants, and two legacy HID posting modes. These runs use the HID insertion point for CGEvent components. Source-state changes do not constitute different insertion points.

Three Accessibility attempts could not locate an actionable field or button. Three vision attempts captured the restricted window but found no field label or disclosure marker. Those six attempts remain inconclusive. The vision attempts sent no input after their target lookup failed.

## Evidence controls

The new runner calibrates each route on a fresh readable reference. It then attacks one unchanged diagnostic process per repetition. A candidate launch requires at least one successful reference, and each candidate route requires its own matched success. The probe hash must still match that reference.

Blind native routes translate a known reference field point through public window geometry. Different window sizes cause refusal before input. The vision route derives its point from its own target image instead.

The oracle counts only submissions after each attempt starts. The private startup action never counts as external success. Input-gate counts also exclude earlier log entries. A new server action takes precedence over tool errors. A block requires a matched success, a completed input adapter, explicit gate refusals, and no admitted input.

All 36 launched processes passed cleanup. All 31 Python checks pass, including startup-action accounting, failed references, geometry changes, tool failures, and cleanup failures. Neither the production browser nor the probe required a rebuild for this milestone.

## Limits

The candidate is InternalKeyboardControl, which has a private startup sequence and no physical device reader. This tests external actions against the loaded application's normal event gate. It does not test a human-bound device session or establish physical usability. No physical-input absence or hardware-attestation claim follows.

The fixture uses a fixed public layout and harmless fake input. These finite trials do not prove resistance for all websites, inspector transports, or OS input paths. Agent-free status remains unproven.
