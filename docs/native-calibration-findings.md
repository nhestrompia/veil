# Native calibration after console recovery

The unlocked console restored native UI access. The existing probe entries were refreshed through System Settings. The same probe executable then reported effective Accessibility, event-posting, and Screen Recording grants. Its mouse-hook check reported no modifying hooks during calibration.

One initial global-input reference completed its task. A broader pass then completed nine of eleven independent reference tasks. Working routes include three event-source states, curved movement, keycodes, two legacy HID posting modes, and two PID-directed keyboard modes. Fully PID-directed mouse input and its window-tagged variant did not complete. Those routes remain inconclusive.

The browser's separate device-input grant is ineffective after its rebuild. Fresh-start candidate results require that existing grant to become effective again. No new candidate result follows from this milestone.

The native controller now always uses InspectableControl as its reference. It skips candidate launches when the same route and repetition lack a successful reference task. A regression check confirms that a failed reference creates no candidate process or trial. All 24 Python checks pass.

The utility filters were stopped during calibration. No experiment reintroduced the earlier physical click failure. The results show that these native routes work in the current isolated setup. They do not identify the cause of the earlier DockDoor interaction or prove general agent resistance.
