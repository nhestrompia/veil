# Native semantics after physical use

Three readable reference sessions exposed the fresh page marker through both the ordinary Accessibility tree and direct focused-element queries. Each exposed its content menus and accepted one task through field-value and button-press actions. All three reference processes passed cleanup.

The same physically calibrated restricted browser remained alive for three matched comparisons. Neither read route recovered the marker. Each returned only two elements. Direct queries included application focus, system focus, and foreground hit tests, with exact target-PID ownership checks.

The File/Edit query succeeded but exposed no content actions. No clipboard content was accessed.

The AX action adapter could not find the fixture field or button. It sent no field write or button press, and no new accepted task appeared. Its status remains inconclusive. These are unavailable semantic targets, not measured input-gate refusals.

The [saved results](evidence/source-policy-semantics-results.json) retain every query, oracle delta, binary identity, and cleanup result. The browser and probe stayed unchanged. No permission changed.

## Controller and checks

The controller requires physical completion and binding in the unchanged session. Each reference must recover its own marker through both read routes, expose content menus, and complete the task before candidate queries run. Three checks enforce those separate control requirements.

## Limits

The read results cover the exact browser PID and the probe's public Accessibility queries. They do not prove that every remote accessibility object or renderer process is inaccessible. The action adapter's unavailable target remains an open result under the strict acceptance gate.

The absence of a content menu closes only the tested menu surface. It does not authenticate physical keys or protect every capture, inspector, or session channel. The browser remains unproven as agent-free.
